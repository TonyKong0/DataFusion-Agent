# V4 复杂文档评测（Phase 40）

来源版本：V4 / Phase 31–40，v1.4 前的历史评测。本文件的样本与结果保持原样，不代表当前应用版本的当轮测试。

评测脚本为 `backend/tests/evaluate_document_v4.py`，逐例记录见 [离线结果](evaluation_document_v4_results.json)和 [BGE-M3 + DeepSeek 实测结果](evaluation_document_v4_live.json)。用例是项目内生成的受控样本，测试模块行为与回归，不等于对未知真实报告的泛化准确率。

| 任务 | 样本与结果 | 口径 |
| --- | --- | --- |
| 公式参数 | 20 例，Precision / Recall / F1 均 100% | 四类模板、五组数值；比较变量名称，另核对唯一绑定 |
| 公式解析与计算 | 20 例，解析与计算均 100% | 增长率、差额、总额、倍数；AST 白名单，单位换算 |
| 非标准目录 | 10 份生成 PDF，标题 P/R、层级准确率均 100% | 十种英文编号/章节样式及版式；中文编号另有单元测试，尚无十份真实中文报告评测 |
| 复杂度策略 | 20 份四档合成文档，策略选择 100%，等级符合预设场景标签 100%，重复评分稳定 | 标签在造样本前按四档场景设定；**不是独立真实文档人工评分** |
| 页级质量 | 8 页受控样本，Issue P/R 均 100% | 覆盖正常、旋转、模糊、扫描、异常字符、空白和低 OCR 置信度；尚未量化真实数据上的 P/R |

扫描 PDF 的端到端导入用一页图片型 PDF 验证：页面进入 RapidOCR，成功读出 `HELLO DOCUMENT 12345`，并记录 OCR 路由和页级元数据。普通文本 PDF 仍跳过 OCR。扫描件可识别不代表所有模糊、倾斜或手写 PDF 都能读对；OCR 无文字时会明确报错。

## V3 固定切片与 V4 层级切片

在 10 份包含明确预算事实的合成英文文档上，分别用旧固定切片和 V4 层级切片，经实际 BGE-M3 检索、DeepSeek 回答：

| 指标 | 固定切片（V3 路径） | 层级切片（V4 路径） |
| --- | ---: | ---: |
| Top-1 事实命中 | 10/10 | 10/10 |
| 答案含正确预算数值 | 10/10 | 10/10 |
| 引用对应真实页和 chunk | 10/10 | 10/10 |
| 检索 + 回答平均耗时 | 1548 ms | 1591 ms |

这组简单样本没有显示 V4 在答案准确率上优于旧方案；两者都答对了。V4 额外返回了可检查的标题路径。耗时差异很小，且每种路径只测十次，不能据此断言 V4 更快。测试未覆盖实际杂乱目录、中文扫描件、复杂表格和低质量照片中的最终问答准确率。离线词面检索代理结果单独保存在 JSON，不作为真实 RAG 结论。

本轮主要失败风险：规则标题可能漏掉未编号且字体信息缺失的标题；公式若跨页、变量同名多值或 OCR 识别错误会拒绝自动计算；扫描检测阈值可能误判混排页面；模糊与繁体比例等质量规则只是提示，不能代替人工审阅。没有使用 OHR-Bench，后续可作为独立外部数据集评估，不是运行依赖。

复现：在 `backend` 目录运行 `python -m tests.evaluate_document_v4`。带 `--live` 会加载本地 BGE-M3 并调用 DeepSeek 20 次，消耗 API 用量。回归测试运行 `python -m pytest tests -q`；前端运行 `npm run build`。
