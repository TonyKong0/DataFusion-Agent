# DataFusion Agent v1.7.0 版本说明

本版本在 V1.7 分支上完成，包含 11-04 的四项迭代与 11-05 的三项收尾：版本号治理与指标真值表、agent 评测的真实测量模式、扫描表格结构还原、嵌套查询受控开放，以及黄金答案集判分、OCR 空白格补检、多表子查询对称开放与本地 CI 门禁。

## 改动

- 版本号收敛到单点真值：`backend/app/core/version.py` 声明 `APP_VERSION = '1.7.0'`，FastAPI 应用与 `/api/health` 均引用该常量；前端侧栏改为从健康检查响应读取版本，取不到时只显示产品名。`package.json`、`package-lock.json`、README、使用说明、部署与架构文档同步为 1.7.0。`backend/tests/test_health.py` 断言后端与前端包版本一致，任一文件单独改动会使测试失败。
- 新建指标真值表 `docs/metrics.json`：48 条指标（46 条已测、2 条明确未测），每条给出源文件与取值路径，另有 C1–C6 六条历史数值冲突的处置口径；引用准确率与答案忠实度保持 `unmeasured`，不使用近似值顶替。`backend/tests/test_metrics_truth_table.py` 逐条回源比对。
- agent 评测新增 live 模式：`backend/scripts/evaluate_agent_v5.py` 支持 `--live --max-api-requests --live-cases`，默认仍为离线且 `api_requests = 0`；live 未设请求上限会以参数错误退出。评测工作台在传入上限时自动切换到 live 并写入独立结果文件。首轮实测结果见 `docs/evaluation_agent_v1.7_live.json`。
- 黄金答案集判分：12 道 live 用例的题目、模型回答与判定经人工逐行确认后落成 `backend/tests/golden_answers_v1.7.json`；评测脚本按数值（1% 容差）、名称包含、拒答语义三种方式判分，输出逐题 verdict 与理由。判分逻辑先用标注轮答案离线验证 12/12 复现人工判定，再跑正式批。
- 扫描页表格结构还原：新增 `backend/app/document/table/structure.py`，按 OCR 文本框的行中心与水平空隙重建单元格矩阵，输出 Markdown 表；`table/qa.py` 在原生表格为空时回退到该管线，并对低置信单元格给出告警。评测脚本 `backend/scripts/evaluate_table_structure.py` 使用栅格化无文字层页面与真实 OCR，结果见 `docs/evaluation_table_structure.json`。
- OCR 空白格补检：整页检测阶段会整格漏掉 1–2 位短数字，提高 DPI 或降低置信阈值都无效。新增结构驱动的空白单元格定向补检——由已检出的行列位置推算 ROI，裁剪后走免检测识别，双路投票只允许第二路增强置信、不允许改写主路结果；恢复格保留低置信标记。评测新增一个"真空单元格"负向对照，并提供 `--no-recovery` 生成同批 A/B 基线 `docs/evaluation_table_structure_baseline.json`。
- 嵌套查询受控开放：新增 `backend/app/sql/scalar_subquery.py` 作为共享白名单，只允许**一个单层、非相关、单表聚合**子查询，且只能出现在 WHERE/HAVING 的比较位；`QueryDSL` 新增 `subquery` 过滤值形态并由编译器渲染为 `列 > (SELECT AVG(列) FROM 表)`。相关子查询、多层嵌套、FROM 子查询、`IN`/`EXISTS`、CTE、UNION 仍被拒绝。
- 多表链路对称开放：探针与真实 LLM 端到端证实多表 DSL 也能编译、校验并执行含子查询的 SQL。期间修复一个真实兼容缺口——模型常输出只有一个子条件的 `AND`/`OR` 组，而 DSL 要求布尔组至少两个条件，归一化层现在将其折叠为单个叶子且不修改原始 payload。
- 本地 CI 门禁：新增 `scripts/verify.ps1`（后端全量回归、前端构建、版本单点真值、cv2 隐性依赖、可选 LLM 连通性，任一步失败即非零退出），`.github/workflows/ci.yml` 作为迁移到 GitHub 后的前瞻配置。实测全量 pytest 在 MySQL 不可达时仍通过，故 CI 不需要数据库服务。
- 启动脚本优先使用 `backend/.venv`（存在时），并同步更新 README、使用说明与部署文档的双 venv 说明。

- 后端全量测试：`cd backend && .venv\Scripts\python.exe -m pytest`，**865 passed, 0 failed**，31.81 秒；相对上一基线 790 项只增不减。
- 前端生产构建：`npm run build`，通过（2.12 秒）。
- 本地门禁：`powershell -ExecutionPolicy Bypass -File scripts/verify.ps1` 五项全绿、退出码 0；另用不存在的 Python 路径做过反向验证，确认失败时返回非零退出码。

- 真值表：48 条指标回源比对通过，6 条冲突均有处置口径。
- 回归报告：`reports/` 四个文件由 `backend/scripts/run_competition_tests.py` 重新生成。

## 实测结果与边界

| 项目 | 结果 | 说明 |
| --- | --- | --- |
| agent live 路由 | 准确率 1.0，LLM 兜底触发 4.55%（5/110） | 路由仍以确定性规则为主 |
| agent live 工具执行 | 完成率 0.5（6 success / 6 partial_success） | 12 例、单环境 |
| agent live 引用 | 结构性合法率 0.5 | partial 用例无 claims，按定义计为不合法 |
| agent live 请求量 | 50 次，上限 220，未截断 | `deepseek-chat`，26,312 tokens |
| agent live 答案准确率 | **0.5**（correct 6 / partial 5 / wrong 1），可接受率 0.92 | 12 题人工确认黄金集；样本小、单模型单环境 |
| 扫描表格还原 | 单元格 **100%（53/53）**、整表 **4/4** | 补检恢复 7 格；同批 A/B 基线 86.79%（46/53）；4 套干净合成版式，含真空格负向对照 |
| 多表标量子查询 | 端到端打通：自然语言 → 含 `(SELECT AVG(...))` 的 SQL → 执行返回 59 行 | 仅 WHERE 级比较；聚合后的 HAVING 级比较仍不支持 |
| CI 门禁 | `verify.ps1` 五项全绿 | GitHub Actions 为前瞻配置，当前 gitee 远程不会触发 |

未覆盖的部分：引用准确率与答案忠实度仍无人工标注；答案准确率的黄金集只有 12 例且一半是"应拒答"题；多表子查询虽能编译执行，但对"消费总额高于平均消费额"这类问题，DSL 只能表达 WHERE 级比较，与用户意图的 HAVING 级聚合比较不等价，模型回答却可能宣称总额达标——**链路打通不等于语义正确**；扫描表格补检只在干净合成版式上验证，7 个恢复格置信度 0.241–0.665 属低置信，`header_assumed = True` 表示首行当表头仍是假设。

## 未覆盖边界

- 持续集成只在本地落地；当前远程为 gitee，`.github/workflows/ci.yml` 不会自动执行，仓库迁移前仍是手工触发门禁。
- 未做冷启动与热态分离的性能测量；live 平均耗时含 BGE-M3 首次加载（约 54.6 秒），不宜作为稳定均值引用。
- 历史评测文档中的手写数字尚未逐份回填真值表，`docs/evaluation-methodology.md` 已就地标注为过期。
- 扫描表格未测倾斜、噪声、合并单元格、中文表头与真实扫描件；补检上限为每表 12 格，大表不会全量补检。
- 多表 DSL 不支持 FROM 子查询与 HAVING 级聚合比较；相关子查询仍被拒绝。
