# DataFusion Agent v1.4.0 集成与稳定性验收

本记录描述从 `origin/master` 的 `35bbb85` 建立的 `v1.4-integration`，仅保留 v1.4 当时的实现与验收结果。后续 v1.5 已从合并提交 `776b6f2` 单独实施，当前状态见 [v1.5 验收](v1.5-release.md)。

## 改动

- 修正 Agent 路由：领域词（如“订单”）出现在文档问题中时，不再自动触发数据库查询；问题明确先查某个来源再查另一个来源时继续按跨源处理。Agent 会话与直接 Agent API 都暴露数据库工具返回的问题理解、Schema Linking、JOIN 规划、SQL 和公开子 Trace。
- 在多表 SQL 的最终 AST 校验中拒绝会被一对多明细 JOIN 放大的父表 `SUM`、`AVG`、`MIN`、`MAX` 和普通 `COUNT` 聚合。`COUNT(DISTINCT ...)` 与明细表聚合保留。
- 为 PDF 解析、切片和索引加入后台任务、按文件保存的阶段/分片进度、失败原因及重试状态。失败或中断的索引可重试；FAISS 文件成功后再原子切换清单，重建失败保留旧索引。前端索引运行时仍可提问、切换会话和管理其他文档。
- 旧上传与重建 API 默认保持同步行为；新增 `background=true` 和索引状态接口供新前端轮询。
- 前端新增问题理解说明和嵌套 Trace 瀑布图，保留现有 Agent Plan、Tool Call、Evidence、Conflict 面板及公开 Trace 边界。
- `package.json`、`package-lock.json` 根包和 FastAPI 应用版本统一为 `1.4.0`。历史评测保留原数据并标注其来源版本。

## 验证

- 基线：改动前后端全量测试 **532 passed**；前端生产构建通过。
- 当前后端：`cd backend; .venv\Scripts\python.exe -m pytest tests -q`，**544 passed**。唯一警告是 Starlette 提示 `httpx` 测试客户端弃用；与本次改动无关。
- 当前前端：`npm run build` 通过，Vite 8.3.1。
- 真实依赖联调：本机 MySQL Chinook 可读（11 张表，59 位客户）、独立会话数据库可用、DeepSeek 调用成功、BGE-M3 本地模型可用。通过 `POST /api/conversations/{id}/query` 逐项验证数据库单源、文档单源、数据库→文档和文档→数据库；四项均 HTTP 200、终态 `success`，两项跨源关联为 `linked`。直接 `POST /api/agent/query` 数据库问题也返回成功和证据。
- 后台上传联调：合成 PDF 上传在 HTTP 请求内快速返回，索引状态最终到达 `indexed` / 100%，并有真实引用页码。测试用临时目录，临时 PDF、索引和会话已删除。
- 当前评测未测真实答案准确率、引用准确率和延迟分布。单次黄金场景只证明本轮指定输入及本机依赖成功，不能推广为一般准确率或性能结论。

## 已知边界

- 运行日志与页面只公开状态、工具和耗时，不公开模型私有推理。
- 后台索引执行器每个进程最多并发处理一份文档；其他文档会保持可见的等待状态。向量生成按 8 个切片一批上报进度，但底层模型编码仍维持 `batch_size=1`；尚未进行多文件吞吐基准，因此不声称索引速度提升。
- MySQL 测试客户端仍有一条 Starlette/httpx 弃用警告。
