- **v1.4：集成和稳定性 PR。** 保留 master 现有页面、API、Agent、文档、多模态和评测能力；定位并修复跨源 Agent 运行故障；吸收经验证的 Tony_Dev SQL 扇出保护、后台索引状态/失败隔离模式，以及前端解释和交互设计。应用版本更新为 `1.4.0`。
- **v1.5：文档会话与索引体验 PR。** 修复同一对话切换文档仍查旧文档、索引期间不能开新对话，以及新增文档索引慢的问题；支持每轮选择多个已索引文档并保留逐轮来源。应用版本更新为 `1.5.0`。
- v1.5 必须在 v1.4 合并后，从更新后的 `origin/master` 单独开分支；不要把两个版本塞进同一个 PR。

## v1.4 实施顺序

### 1. 建立隔离分支并记录基线

1. 检查 `git status`，确认并保留已有未跟踪 ZIP。
2. fetch Gitee 最新 `master`，从 `origin/master` 建立 `v1.4-integration`（或同义清晰名称）工作分支；不从 Tony_Dev 合并或 cherry-pick 整支代码。
3. 在改动前记录 master 当前测试结果、前端构建、应用版本和可运行的黄金场景；检查安装说明、环境配置及会话数据库权限。

### 2. 复现并修复跨源 Agent

按用户可见的完整调用路径诊断，而不是先猜具体故障：

1. 确认 `.env`、MySQL Chinook 连接、会话库连接/DDL 权限、DeepSeek 配置和已索引黄金文档状态；日志和报告不得输出密钥。
2. 启动 master 前后端，分别验证健康接口、数据库单问、文档单问、直接 Agent API，以及创建 `agent` 会话后通过会话 query API 提问。
3. 用黄金问题覆盖数据库单源、文档单源、数据库结果传给文档检索、文档阈值传给 SQL 四条路径；保存 HTTP 状态、终态、工具步骤、证据和耗时。
4. 对比失败请求的会话层、路由、计划校验、工具参数、执行结果和证据融合。添加最小回归后再修；保留失败时的 `CLARIFY` / `REJECT` / `BLOCKED` 语义，不以伪造成功或无依据答案掩盖错误。
5. 如失败由本机账号权限或缺少文档等前置条件造成，改进启动检查和错误提示，并区分环境阻断与代码缺陷；不要为了会话存储给 Chinook 业务账号增加写权限。

**完成标准：**会话 API 的跨源回归可以在测试配置中复现成功；四条黄金路径按其预期执行或给出可解释、可行动的阻断；运行说明准确描述必要配置。

### 3. 选择性吸收 Tony_Dev 后端经验

- **SQL 扇出保护：**检查 master 多表验证器是否保护“一对多明细 JOIN 后对父表金额重复聚合”。若缺失，将 Tony 的规则移植到 master 的最终 SQL 校验边界，针对正例、拒绝例和 `COUNT(DISTINCT ...)` 等安全情况加回归。Schema Linking/Planner 不能代替最后的 AST 校验。
- **后台索引状态与失败隔离：**保留 master 当前 PDF 解析和公式、OCR、层级切片、多模态数据；只借鉴 Tony 的异步任务状态、阶段进度、失败隔离、可重试和原子发布模式。单文件失败不得阻断其他文件；只有索引可用的文件可检索。维持旧上传/API 客户端兼容。
- **有界上下文：**审查 master conversation 的近期轮数、摘要、LLM 预算是否覆盖所有问数与跨源入口。master 已有服务端会话摘要和调用预算；只补真实缺口，不复制 Tony 的第二套上下文状态。
- **索引速度：**本阶段提供可观测阶段和失败状态；吞吐调优及索引期间完整交互解耦归 v1.5。Tony 的 `embed(batch_size=1)` 与向量分批本身不证明更快，不按代码外观移植性能结论。

### 4. 选择性吸收 Tony_Dev 前端设计与交互

## v1.5 实施顺序

### 1. 分离会话选择与索引状态

把前端的全局 `busy` 拆成问答忙碌和按文档维护的索引任务状态。索引期间仍可新建对话、切换历史对话、继续数据库问答，以及查询其他已索引文档；正在索引的文档不可选为查询来源。只禁用会与同一文档索引冲突的重建/删除等动作，并保持状态轮询和错误可见。已确认“上传期间可新建对话”；回归验收仍需覆盖切换已有会话、数据库问答和查询其他已索引文档，避免只验证单一按钮。

### 2. 逐轮文档范围和多文档来源

- 文档问答的每轮请求在发送时快照当前所选的一个或多个已索引 `document_ids`；服务端对去重后的集合做验证，并使用 master 已有的多文档检索和证据能力。
- 联合搜索上限统一为 **10 份不同文档**：同步调整会话/RAG/多模态 API 校验、服务层、检索层、路由层、前端选择提示及 API 文档。单文档路径保持不变；用 1、2、10 份验证可用，用 11 份验证得到明确且可操作的错误，不能让不同入口出现 8/10 不一致。
- 会话 query API 增加可选逐轮 `document_ids`。字段缺省时为旧客户端兼容，沿用会话原先绑定的单个 `document_id`；字段显式提供时，以该列表作为本轮精确范围。显式空列表表示本轮没有选择文档，文档问答返回明确的“请选择文档”状态，不偷偷退回旧范围或全库检索。
- 沿用当前会话表结构；将本轮实际 `document_ids`、文件名和引用保存在该轮结果中。历史回答始终按其结果中保存的来源渲染，不读取当前选择器值来重算旧来源。
- 打开已有会话时，默认恢复最后一轮实际使用的文档集合；用户仍可在下一轮发送前更换选择。已删除或不可用的历史来源保留为历史信息，同时提示不可继续检索。
- 逐轮范围适用于普通文档问答。跨源 Agent 保留 master 现有单文档工具契约；除非跨源黄金测试证明多文档是所需能力，不扩展它的路由和工具协议。
- 为跨源 Agent 增加有独立预期结果的路由用例：问题明确要求数据库事实或要求把 PDF 中提取的条件用于数据库查询时，断言实际执行 `database_query` 并返回数据库证据；相似领域词但明确只询问 PDF 内容时，断言不会多余调用数据库。路由以问题意图和用户指定来源为准，不以单个领域词作为唯一触发条件。
- 对已有单文档 `/api/rag/query` 客户端保持兼容。如为其增加 `document_ids`，旧 `document_id` 请求仍按单文档工作；若新旧字段同时提供，只有二者表达同一个单文档范围时才接受，否则返回明确的范围冲突错误。

### 3. 索引吞吐测量和优化

先修复性能/跨源实测所需的黄金 PDF 前置条件：将生成脚本依赖声明在测试/开发依赖中（或改用仓库已安装的 PDF 生成能力），在测试说明中给出安装和生成命令，并在生成前检查依赖与 `C:\Windows\Fonts\simhei.ttf`。缺少任一条件时应给出清楚的环境阻断提示，不能以“测试通过”代替未生成的黄金资料。生成后核对页数、关键文本和阈值，再用于上传、索引、文档检索及“提取阈值后查询 Chinook”的跨源黄金用例。

然后用相同机器、模型、缓存状态和代表性 PDF 记录冷启动/热态、解析、切片、Embedding、写索引耗时和 chunk 数；区分首次模型加载与每 chunk 编码成本。基于数据调 Embedding batch size、任务并发或向量构建路径，控制内存并让同一模型所有文档索引保持一致。新索引完整成功后再原子替换旧索引；失败时标为失败并保留旧索引。性能报告记录优化前后相同口径数据，不能把一次热态样本宣传为普遍延迟。

### 4. 前端行为与版本验证

选择器采用 master 风格的多选控件，借鉴 Tony 的选中态、全部/取消全选、索引状态和片段进度；问答期间锁定本轮请求范围，用户变更只影响下一轮。提供明确选中数量和空选择状态，界面文案统一说明最多 10 份。历史轮次的文档名、引用与预览绑定到各自结果。

跨源回答采用“答案优先”的阅读顺序：先呈现面向用户的结论或结果摘要；数据库行以有标签的表格/字段和值呈现，不把原始 JSON 或 `ev_*` 内部 ID 当作答案正文；PDF 与数据库来源以可读的引用/来源标记关联到答案。问题理解、Schema Linking、SQL/工具执行过程、完整证据和诊断信息放在答案之后的次级区域或可展开详情里，保留核查能力但不抢占主视觉。澄清、拒答、部分成功和来源冲突仍需显著且准确地表达，不能为了突出答案而隐藏不确定性。

用桌面和窄屏核对主答案的视觉层级、换行和引用可读性；标题层级连续，正文字号和对比度足以快速扫描，详情控件可键盘操作并有清楚的展开状态。UI/UX Pro Max 的定向查询没有找到专门的聊天答案卡片匹配项；这里采用其通用层级建议（语义化标题、统一字号层级、可访问交互）作为设计基线。

将 `package.json`、`package-lock.json` 根包版本和 FastAPI 应用版本统一改为 `1.5.0`，更新当前文档版本引用并保留 v1.4 历史记录。验证后端全量测试、前端构建、RAG API 兼容、会话 API 兼容、逐轮切换与 10 文档边界、跨源路由黄金问题、答案优先布局、黄金 PDF 生成、索引期间并行交互、索引失败保留旧索引和吞吐基准。报告分别记录自动断言、真实 MySQL/模型/PDF 联调结果及环境阻断。

**完成标准：**同一对话先查文档 A/B，再换成 C 后，新轮只检索 C；历史轮仍显示原先 A/B 的引用；显式多选只从选中文档集合产生引用；联合搜索接受最多 10 份并明确拒绝 11 份；索引期间可以开新对话和查询其他已索引资料；失败索引不覆盖可用旧索引；API 旧调用方式保持可用；需要数据库事实的黄金问题确实执行数据库工具，文档专属控制问题不会误查数据库；黄金 PDF 可按说明生成并完成跨源验证；主答案醒目、结构化且不暴露原始 JSON/内部证据 ID 为正文。
