# DataFusion Agent v1.5.0 文档会话与索引体验验收

本版本基于已合并到 `master` 的 v1.4.0（`776b6f2`），在 `v1.5-doc-session-index` 独立实施。

## 改动

- 文档会话支持每轮选择 1–10 份已索引 PDF。请求发送时固定本轮范围，服务端去重并验证，结果保存实际文档 ID、文件名和引用；打开历史会话时恢复最近一轮使用的范围，旧轮引用继续使用当轮保存的数据。
- 会话 query API 支持可选 `document_ids`。省略时继续使用旧会话绑定的单份文档；显式空列表会返回“请选择文档”，不会退回旧范围。无状态 RAG 同时保留旧 `document_id` 请求，并支持新多文档字段。
- 索引任务与问答忙碌状态分开。上传/索引期间可以新建或切换会话、运行数据库问答，并查询其他已索引文档；索引中的资料不能加入当前查询范围。
- 文档、多模态路由和检索统一最多 10 份，超过 10 份返回可识别的 422 错误；同一 ID 重复选择按一份计算。
- 跨源回答先显示可读结论，数据库行格式化为字段和值；问题理解、Schema Linking、SQL 和工具详情保留在次级区域。答案正文不显示原始 JSON 或内部 `ev_*` ID。数据库路由按来源意图和动作判断，文档内出现数据库领域词本身不会触发数据库查询。
- 黄金 PDF 生成器把 ReportLab 声明为开发依赖，先检查依赖和 Windows 黑体字体，支持自选输出路径且拒绝覆盖已有文件。
- BGE-M3 编码批大小调整为 4。所有索引仍按 8 个切片报告进度。
- npm 根包和 FastAPI 应用版本统一为 `1.5.0`。

## 自动化验证

- 后端全量测试：`cd backend; .venv\Scripts\python.exe -m pytest tests -q`，**572 passed**。包含逐轮范围切换、历史来源保存、旧请求兼容、1/2/10/11 份边界、跨源意图路由和答案格式回归。唯一警告为 Starlette 对当前 `httpx` 测试客户端用法的弃用提示。
- 前端生产构建：`npm run build`，通过（Vite 8.3.1）。
- 空白检查：`git diff --check`，通过；Git 只提示现有工作区文件将由 LF 转为 CRLF。
- 跨源路由额外回归覆盖“用手册里的标准检查数据库客户记录”与“文档里讲了如何检查数据库客户记录吗？”：前者要求两个来源，后者只查询文档。

## 本机黄金资料联调

使用临时输出生成合成 PDF，未覆盖仓库中原有的 `output/pdf/chinook_golden_demo.pdf`。PDF 预览为 1 页，包含 Invoice 表映射、`Invoice.Total > 5` 阈值和 Rock 音乐类型文本。实际 PDF→索引→跨源查询中，Agent 调用了文档和数据库工具，SQL 使用 `Invoice.Total > 5`，返回 179 张发票，并把结果关联到 PDF 来源。文档专属控制问题只调用文档检索。

这证明本机黄金输入的指定调用路径可用；单个问题不能代表通用答案准确率或引用准确率。MySQL、BGE-M3 和 DeepSeek 联调依赖本机配置。黄金 PDF 生成命令与 ReportLab 安装方式见[部署说明](deployment.md)。

## 索引吞吐观测

在本机 CPU、模型已热启动时，对 40 条平均约 187 字符的输入比较 Embedding 批大小 1、4、8，中位耗时分别为 13,168、9,453、9,569 毫秒，因此采用批大小 4。对黄金 PDF 的 10 个切片，热态 Embedding/build 测得中位数 2,408 毫秒；v1.4 的一个热态基准样本为 3,082 毫秒。后一个对照只有单个基线样本，未测峰值内存，也未形成多文件端到端吞吐分布；这些数据用于选择本机批大小，不作为普遍加速或内存改善结论。

## 未覆盖边界

- 当前未对多文件并发索引进行端到端延迟分布或峰值内存测试；索引任务仍按进程内既有并发策略运行。
- 浏览器桌面与窄屏的自动截图回归未配置；本轮完成生产构建及组件/样式核对。
- 历史记录保留其原始结果。跨源回答结构与逐轮文档范围不改变 v1.4 的 API 数据存储表结构。
