# V3 结构化问数评测（Phase 30）

历史来源版本：V3 / Phase 21–30，v1.4 前的评测结果。

2026-09-29 在本地 Chinook MySQL 与当前 DeepSeek 配置下，按固定 50 题运行多表问数：两表 20 题、三表 15 题、分组聚合 10 题、复合条件 5 题。问题和独立参考 SQL 保存在 `backend/tests/multitable_cases_v3.py`，逐例运行结果见 [evaluation_multitable_v3_live.json](evaluation_multitable_v3_live.json)；[离线结果](evaluation_multitable_v3_offline.json) 用于复核候选、路径和参考 SQL。

| 指标 | 本轮实测 | 口径 |
| --- | ---: | --- |
| 多表意图识别 | 50/50，100% | 问题进入 V3 多表链路 |
| 选表正确 | 50/50，100% | 选中表均属于标注表，规划包含全部标注表 |
| JOIN Path Accuracy | 50/50，100% | 表集合与标注一致且每条边来自真实外键 |
| SQL Syntax Accuracy | 50/50，100% | 返回的 SQL 可解析为单条 SELECT |
| Execution Accuracy | 50/50，100% | 通过安全校验并在只读事务中执行 |
| Result Accuracy（严格） | 38/50，76% | 返回行、列值及被截取的行集合与参考 SQL 完全一致；忽略无关顺序但不忽略额外展示列 |
| Aggregate Value Accuracy | 46/50，92% | 只比较聚合值集合，不证明对应对象名称一致 |

严格结果不一致的 12 题中，多数 SQL 返回了额外的姓名或 ID 字段，或在题目没有要求顺序时使用了与参考 SQL 不同的排序。四条“每位艺术家/每张专辑”分组题的聚合值集合也未对齐：结果超过 100 行，模型与参考 SQL 截取了不同的 100 组。它们不能直接判为数值计算错误，也不能直接算作答对。下阶段若扩展评测，应给这类问题加入明确排序与稳定的实体键比较，再核对完整结果。此处保留严格口径和原始 SQL，未人为提高得分。

安全性检查覆盖未知表/字段、伪造 JOIN、无条件 JOIN、写操作、子查询、多语句和危险函数。修复最多 2 次；每次修复后重新进行同样的 SQL 校验。50 题均执行成功，不能推断所有未知问题都能成功。

## V2 / V3 对比

V2 的语义层按单表能力校验；对这 50 条跨表题，规则路径有 43/50 会在 SQL 生成前澄清。其余 7 条也仍受 V2 单表 SQL 生成器和无 JOIN 校验约束，因此本报告没有给 V2 虚构一个“查询准确率”。V3 保留原单表链路，同时对明确的跨表意图使用真实 Schema、外键路径和多表校验，50/50 在本轮生成并执行只读 SQL。[V2 原有六题配对实验](evaluation_v2.md)仍是单独基线，不能直接与这 50 题的耗时或准确率比较。

两个数据集均由本项目人工整理，答案依赖当前 Chinook 数据版本、模型响应和 100 行上限，不是外部盲测。运行 `python -m tests.evaluate_multitable_v3 --live` 会调用 DeepSeek 50 次并连接 MySQL；运行 `python -m tests.evaluate_multitable_v3` 仅做离线结构与参考 SQL 检查。
